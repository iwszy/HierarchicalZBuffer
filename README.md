# 层次 Z-Buffer 消隐算法实现

用 C++14 从零实现的一组**消隐（hidden surface removal）算法**对比程序。全部算法手工光栅化，
**不调用任何图形 API**（无 OpenGL / DirectX / GPU），仅依赖 [glm](https://github.com/g-truc/glm)
做向量矩阵运算、[stb](https://github.com/nothings/stb) 输出 PNG。

程序依次读入 `models/` 下的 6 个 OBJ 模型（1.7K ~ 213K 面片），
分别用 5 种算法渲染 1024×1024 的图，把结果写入 `results/` 并在控制台打印耗时。

## 实现的算法

| 算法 | 说明 |
|---|---|
| 普通 Z-Buffer | 逐三角形求包围盒，盒内每个像素用重心坐标判内外，再做深度测试。作为朴素基线 |
| 经典扫描线 Z-Buffer | 图像序。建立分类边表（ET），逐扫描行维护活化边表（AET）与边对，行内增量递推 x 与深度 |
| 特化扫描线 Z-Buffer | 图元序。逐个三角形处理，按其跨越的扫描行推进，跨行状态全部放在函数栈上的局部变量里，不需要任何全局表 |
| 简单模式层次 Z-Buffer | 用四叉树维护 Z-Buffer（每节点存该区域最大深度），三角形先与该区域最大深度比较，被完全遮挡则跳过光栅化 |
| 完整模式层次 Z-Buffer | 在简单模式基础上叠加屏幕空间 BVH，自上而下递归，只对未被遮挡的叶子节点光栅化 |

## 构建与运行

```
环境：Windows + Visual Studio 2022（v143），C++14
依赖：include/glm、src/stb_image*.hpp 均已随仓库提供，无需额外配置

直接打开 HierarchicalZBuffer.sln，选择 Release | x64 运行即可。
程序的工作目录需要是工程根目录（要读 models/、写 results/），
```

> 性能数据请务必在 **Release** 配置下采集。Debug 配置下 glm 的模板数学无法内联，
> 光栅化部分会慢 10~30 倍，而四叉树建立（以堆分配为主）只慢约 1.1 倍，

几点观察：

- **普通 Z-Buffer 的耗时与包围盒面积成正比，而不是面数**。所以 `robot.obj`（188K 面）
  比 `armadillo.obj`（213K 面）慢得多——前者的三角形在屏幕上更大，
  包围盒内的无效像素更多。
- **层次 Z-Buffer 目前被四叉树的建树时间主导**：1024×1024 的四叉树有 1 398 101 个节点，
  每节点 2 次堆分配、约 100 MB 内存，建树需要约 92 ms，且与模型面数无关
  （只与屏幕分辨率有关），是下一步的主要优化对象。
- 六个模型都是**单个封闭凸物体**，遮挡关系简单，因此层次 Z-Buffer 的剔除收益有限；
  它真正的用武之地是遮挡关系复杂、且加速结构可以跨帧复用的场景。

## 实现要点

**共用的扫描线光栅化内核**（`triangleRasterizer.hpp`）
把三角形按扫描线切成"上半部分 / 下半部分 / 退化成水平线"三种情况，逐行从左到右遍历，
用平面方程解出的 dzx、dzy 递推深度。各算法只有"深度测试 + 写入深度"这一步不同
（普通 z-Buffer 写 Z-Buffer；层次 z-Buffer 还要把四叉树逐级向上更新），
因此把它做成回调参数、经模板内联展开，**三个类合计 515 行重复代码收敛为 201 行共享实现**。

**四叉树 Z-Buffer**
每个节点记录该像素区域的**最大深度**。三角形光栅化前先找到能覆盖它的最小四叉树节点，
若三角形最小深度大于该节点的最大深度，说明整个三角形被已有几何完全遮挡，直接跳过。
写入像素后需要沿父链向上更新区域最大深度，且只在值真的变化时才继续向上走。

**BVH（完整模式）**
按循环轴 + 中位数划分构建二叉树，叶子节点保存三角形 ID。渲染时从根节点开始递归，
每个 BVH 节点先定位到能包含它的最小四叉树节点，再与被遮挡判断结合。

**顶点 y 坐标取整**
相邻三角形共享一条边。若不把顶点 y 取整，浮点误差会让这条边在两个三角形里算出不同的
起始扫描行，屏幕上会出现裂缝。取整后两侧必然落在同一行。

**边对的左右判定**
只有一条边时先把它当作左边界存放；第二条边到达时判左右。这里**必须分两种情况**：
两条边共用上顶点时（普通三角形）此刻 x 完全相同，只能比较每扫描行的 x 增量 dx；
共用下顶点时（上平底三角形）此刻 x 不同，且 dx 的大小关系与左右**相反**
（设两条边从 xp、xq 收敛到底顶点 xr、跨越 H 行，则 d1 = (xr−xp)/H、d2 = (xr−xq)/H，
因 H > 0 故 d1 < d2 等价于 xp > xq），此时必须直接比较 x。

## 已知局限与后续工作

- **四叉树是当前性能瓶颈**：1.4M 个堆节点，建树约 92 ms、约 100 MB。
  换成 Greene 1993 原始层次 Z-Buffer 的扁平 Z-max 金字塔（mipmap 式数组）后，
  内存可降到 5.6 MB、建树降到 1~2 ms 量级。
- **BVH 建在屏幕空间**（MVP 之后），相机一动就必须重建，
  因此加速结构无法跨帧复用。改成物体空间 BVH + 每帧只重建 Z 金字塔才是层次
  Z-Buffer 的标准做法。
- **BVH 遍历没有前后排序**，遮挡剔除的效果依赖运气；按到相机的距离排序可以显著提高剔除率。
- 尚未实现视口裁剪：目前是把扫描线与包围盒夹取到窗口内保证不越界，
  真正的多边形裁剪（Sutherland-Hodgman / 近裁剪面）还没做。
- 深度并列时的仲裁顺序取决于数据结构遍历顺序，不同实现会得到极少量不同的像素。
  需要完全可复现的输出时，应当显式规定仲裁规则（例如按三角形 ID 排序）。
